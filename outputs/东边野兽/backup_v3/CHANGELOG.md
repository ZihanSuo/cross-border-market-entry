## 对应改动了什么配置（推断，非精确 commit 记录）

项目没有接入 git，无法看到 v2→v3 之间的精确 diff。以下是拿**当前** `config/tasks/*.yaml` 的结构去对照 v3 输出结构、结合 backup_v2 CHANGELOG 结尾"下一轮 v3 目标"倒推出来的对应关系，可信度高但不是逐行 diff：

1. `market_feasibility.yaml` 大改：加入"建议（一页纸）"expected_output 结构、门槛语义四态硬规则（B3）、加权评分表（权重合计 1.0）、90 天验证动作格式、空话禁令（A1，禁止把任命 RP 当核心洞察）。
2. `competitor_analysis.yaml` 加入品类对齐要求（面部护肤对比面部护肤，不能用身体乳对比精华油）+ "代表 SKU + £ 标价 + 商品页 URL"强制要求。
3. `market_expansion.yaml` 加入"路径对比表"结构（适合理由/上游条件/风险/置信度/依据 URL）。
4. **没有改的（这轮的遗留问题）**：`briefs/herbeast_uk_v2.json` 的 `constraints` 字段里其实已经明确写了"数字与价格必须 https 商品页或权威页；禁止空引用与 example.com"——这条约束通过 `{brief}` 会注入到**每一个** task 的 description 里，`market_expansion_task` 也不例外。但 v3 的 `market_expansion.md` 还是编了 `example.com`——说明这一轮改的是**输出结构**（task 的 `expected_output`/硬规则），没有解决"模型会不会真的遵守 brief 里已经写明的规则"这个问题。这正是后来（这次会话）加引用校验层要解决的事：光把规则写进 prompt 不够，得有代码层面去核实模型有没有照做。

## 面试怎么一句话讲 v2→v3

> 第二轮虽然有链接了，但结构还是通用研究报告的样子，竞品也没有具体价格。我把 task 改成决策备忘录结构——一页纸建议、门槛清单分行业标配/品牌特有、加权评分表、竞品强制要求 SKU 和标价——结构立刻像样了很多。但同一轮里也第一次出现了模型编造 `example.com` 假链接、参考文献表格干脆不填这种问题，说明"prompt 里写了规则"跟"模型真的遵守"是两回事，这也是我后来专门加一层不依赖模型自评的机械引用校验的直接原因。
