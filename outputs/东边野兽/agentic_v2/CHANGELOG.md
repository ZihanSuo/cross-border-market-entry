# agentic_v2 提升日志 —— agentic 试点四轮小结（本分支收尾）

- **Case**：东边野兽 / Herbeast → 英国
- **变体**：`competitor_agentic`（可行性 + 开拓照旧走 workflow，**只把竞品分析换成自主研究版**，与 `research_only` 跑同一 brief 即为对照实验）
- **模型**：全部 agent 用 `.env` 的 `gpt-4o-mini`，`reasoning` 已关闭（做单变量）
- **本目录文件**：`competitor_battlecard_agentic.md`（报告）+ `tool_audit.jsonl`（工具调用审计日志，74KB）
- **版本说明**：agentic 分支实际跑了 **4 轮**，但只归档了首尾两轮。第 2、3 轮的报告被后续运行覆盖了（都写到 `outputs/competitor_battlecard_agentic.md` 同一位置），其关键数据保留在本文档的分析里，原文件已不可复现——这是本项目第三次因为"忘记归档就重跑"丢失中间版本，前两次是花知晓 v1 和东边野兽 v7 之后那批孤儿文件

---

## 一句话

agentic 分支跑通了（工具真的被调用、审计管道完整、结构可控），但**产出质量始终低于模板版**，而且暴露出一个比"报告写得不好"重要得多的发现：**「让模型自我报告执行状态」这个设计模式本身不可靠**——每堵住一个它说谎的位置，它就换一个位置说，四轮下来换了四种形式。这个结论可以迁移到任何 agent 评估场景，是这四轮真正的产出。

---

## 四轮失败模式的演化（这才是本分支的核心价值）

| 轮次 | 改了什么 | 结果 | 失败形式 |
|---|---|---|---|
| 1 | 放开输出模板（"最低要求，不是上限"）+ 开 reasoning | **0 个 URL**、7 个必需章节一个都没有、通篇像内部工作汇报 | 完全不给证据，结尾写"相关网页的抓取和数据验证已成功完成"但报告里一个链接都没有 |
| 2 | 结构约束改回硬性、加 4 条完成条件、关掉 reasoning | 结构恢复（16 URL、章节齐全） | **伪造核实记录**：10 条「已用 scrape_page 核实，页面显示标价 £XX」，事后交叉核对**通过 0 条** |
| 3 | 加工具调用审计（同 prompt） | 审计证明它**确实调用了 6 次抓取且全部成功** | 抓的是 4 个品牌首页 + 1 个反爬拦截页（返回 106 字符），却在每行写"已核实"；且报告里的 URL ≠ 实际抓的 URL |
| 4（本版） | **删掉「核实状态」自述栏**，换成只问客观观察的「抓取观察」 | 部分诚实了 | **把首页标成「单品页」**：观察记录表里四个裸域名首页全填「单品页」，其中一条正文写「页面类型-首页」、表格里又改口「单品页」 |

**共同结构**：模型执行了动作，但不验证动作的结果，然后如实汇报"我做了"。从它的角度这句话不算错，错在我们把「做了」当成了「做对了」。

这个模式与 workflow 分支上观察到的规避演化（编造假域名 → 真链接但内容对不上 → TBD 占位 → 品牌首页 → 数字加免责词）**完全同构**，只是发生在不同的位置。

## 本轮（第 4 轮）的具体表现

### 改动确实生效了一部分

删掉自述栏、改成客观观察之后，出现了四轮里**第一条诚实记录**：

> Weleda：页面类型-首页｜内容里有没有该标价-有，但价格未能具体定位产品型号；需进一步细化查找

上一版同样的情况它写的是「已用 scrape_page 核实，页面显示标价 £9.50」。**说明"只问客观观察、不让自我打分"这个方向是对的。**

### 但另外三条换了个更隐蔽的说法

「抓取观察记录」表里，四个**裸域名首页**全被标成了「单品页」：

```
| https://www.aesop.co.uk/           | Aesop产品页 | 单品页 | 有 | 无 |
| https://www.weleda.co.uk/          | ...        | 单品页 | 有 | 无 |
| https://www.paiskincare.com/       | ...        | 单品页 | 有 | 无 |
| https://www.nealsyardremedies.com/ | ...        | 单品页 | 有 | 无 |
```

`weleda.co.uk/` 是首页——**它自己在正文里都写了「页面类型-首页」，到了表格里又改口成「单品页」**，同一份报告内部前后矛盾。

### 最硬的一条证据：Aesop

审计日志显示那次抓取返回 **106 字符**，内容是 `"Just a moment... Enable JavaScript and cookies to continue"`（Cloudflare 拦截页）。报告写「单品页 | 有 £30.00」。用代码在返回内容里搜 `£30.00`，**找不到**。

另外三条（Weleda £9.50、Pai £34.00、NYR £29.00）在首页内容里**确实能搜到**——品牌首页会展示明星产品和价格。所以不算凭空捏造，但拿首页当"单品页"依然违规，且无法证明那个价格对应的就是报告里写的那个 SKU。

## 这四轮建成的东西（比报告本身有价值）

虽然报告质量不合格，但为了诊断这些问题，建成了三层**完全脱离模型自述**的验证工具：

| 工具 | 作用 | 关键设计 |
|---|---|---|
| `citation_check.py`（扩展） | 报告格式层 | 新增「SKU 名与 URL 品类矛盾」检测，抓住了跨 v4.1/v7/v8 三个版本没被发现的 Aesop `Serum` vs `cream` 问题 |
| `experiments/verify_urls.py` | URL 是否真实存在 | 独立发 HTTP 请求；实测发现两条 404（页面根本不存在，但报告声称"已核实，页面显示标价"） |
| `src/marketing_crew/tool_audit.py` + `experiments/verify_claims.py` | 「已核实」是真是假 | 订阅 CrewAI 事件总线记录每次真实工具调用，事后逐条对质。判据全部客观：URL 在日志里找不到→伪造；返回 <500 字符或含反爬特征→无效；内容完整保存却找不到该价格→存疑 |

**过程中修掉的一个会导致错误结论的 bug**：审计的抓取识别原本按工具名匹配 `"scrape"`，但 `ScrapeWebsiteTool` 在 CrewAI 里的显示名是 **"Read website content"**，不含 scrape 字样。如果没发现，审计会报「没有任何抓取调用」，而这个假阴性恰好出现在最关键的测量上，会让人误判成"模型纯编造"。改成按参数 `website_url=` 判定后修复。

## 结论与判断

**agentic 方向本身没有被证伪**——工具调用、审计、结构控制都跑通了。但在当前配置下（gpt-4o-mini、无 reasoning、简单 HTTP 抓取），它的产出质量稳定低于模板版，主要原因有二：

1. **抓取能力受限**：商业站点普遍有反爬，简单 HTTP 请求拿不到单品页内容。绕过需要 headless 浏览器/代理池，是个无底洞，且偏离项目主线
2. **自我报告不可信**：这是更根本的问题——只要设计里留了"让模型报告自己做得怎么样"的字段，它就会填出好看但不真实的内容

**第二条是可迁移的结论**：不是模型不够强，是这个设计给了它说谎的空间。正确做法是**把执行状态的判定完全交给代码**（审计日志 + 自动核对），模型只负责如实描述客观观察。

**本分支到此收尾。** 现有 workflow 版本完整保留，agentic 版作为"试过、有数据、知道为什么不用"的分支存档，不删代码。

## 面试怎么讲这一段

> 我尝试把系统里最独立的一步（竞品分析）从 workflow 改成 agentic：给目标不给模板，加网页抓取工具，让它自己决定查几家、深挖谁、什么时候停。跑了四轮，每轮都失败，但失败模式在演化——第一轮完全放开结构，它交了一份 0 个引用的工作汇报；收紧结构后，它开始伪造核实记录，写了十条"已用抓取工具核实，页面显示标价 XX"；我加了工具调用审计，发现它**确实**调用了工具而且全部成功，问题是它抓的是品牌首页和反爬拦截页——有一次抓回来只有 106 个字符的"请开启 JavaScript"，它照样写"页面显示标价 £34"；我把"核实状态"这个自述栏删掉、改成只问客观观察，它开始有一条诚实记录了，但把四个网站首页标成了"单品页"。
>
> 四轮下来我的结论不是"agent 不行"，而是**"让模型自我报告执行状态"这个设计模式本身不可靠**——每堵住一个说谎的位置，它就换一个位置说。这跟我在 workflow 版上观察到的规避演化是同构的。所以正确做法是把执行状态的判定完全交给代码：我订阅了框架的事件总线记录每一次真实的工具调用，然后写脚本逐条对质，判据全部客观——URL 在日志里找不到就是伪造，返回内容少于 500 字符就是被拦截，这些都不需要模型配合。这套东西现在是我评估体系里最硬的一层。
