# backup_v7 提升日志（相对 backup_v6）—— QA 换推理模型的对照实验

- **Case**：东边野兽 / Herbeast → 英国
- **变体**：`research_qa`（可行性 + 开拓 + 竞品 + QA），与 v6 完全一致
- **唯一变量**：`agents.yaml` 里 `brand_qa_checker` 的 `llm` 从注释状态改为 `o4-mini`（推理模型）。其余 8 个 agent 全部保持 `.env` 的 `gpt-4o-mini` 不变，`market_feasibility.yaml`/`market_expansion.yaml`/`competitor_analysis.yaml`/`qa_review.yaml` 四份 prompt 一个字没改
- **实验问题**：v6 首次跑通 QA 时结论是「跑通了但不可用」（两处误报、一处自相矛盾、真问题零命中）。这一版要回答的是：**这是模型能力问题，还是任务设计问题？**
- **对比方式**：QA 输出的每一条判断都回查了 `market_feasibility.yaml` 的规则原文与 `briefs/herbeast_uk_v2.json` 的实际内容；研究三份另跑 `citation_check.py --locale uk`
- **重要说明**：研究三份是本次重新生成的（QA 的 context 只认本次运行构建的 Task 对象，读不到磁盘上 v6 的旧文件），所以三份研究报告的内容与 v6 不同。**本版对比的是「QA 在给定材料上的核对能力」，不是「两份研究报告谁更好」**

---

## 一句话

换成推理模型之后，QA 从「不可用」变成了**真的能抓到东西**——v6 那三个毛病（两处误报 + 自相矛盾）全部消失，并且抓到了三件机械校验查不到的问题，其中一件必须回查 brief 原文才能发现。但同时，机械校验也抓到了三处 QA 完全漏掉的问题。**所以结论不是「QA 更强了」，而是两者查的东西不一样，互补而非替代。**

## v6 的三个失败，本版全部修复

| v6 的问题（gpt-4o-mini） | v7 表现（o4-mini） |
|---|---|
| **误报一**：把 `ctpa.org.uk/resources-claims`（带路径）判为「首页证据」 | ✅ 修复。本版同一域名的链接被正确判为「正常 / 相关」 |
| **误报二**：把合法状态值「品牌侧未知」判为违规，要求改成「规则已核实」 | ✅ 修复。本版写「所有状态均为『规则已核实』，符合允许值（规则已核实 / 品牌侧未完成/未知 / 待验证（市场假设）/ 红线），未发现违规」——**准确复述了四个合法值**，说明它这次真的读了规则而不是凭印象 |
| **自相矛盾**：列了阻塞问题，却把「上线前检查清单」六项全部打勾 | ✅ 修复。本版检查清单有两项**明确未打勾**（「无机构首页当数据证据」「品牌表达跨文件一致」），与上面列出的三条阻塞问题一一对应，前后一致 |

## QA 抓到了三件机械校验查不到的问题

| # | QA 的发现 | 回查核实结果 |
|---|---|---|
| 1 | `https://weleda.co.uk` 被当作「UK 草本产品认知度」的证据 | ✅ 属实。该 URL 是**裸域名首页无任何路径**，而且在证据摘要表里被标为 **A 级证据**。`citation_check.py` 漏掉的原因：它的首页黑名单 `KNOWN_RESEARCH_HOMEPAGES` 只有 statista/mintel/euromonitor/grandviewresearch 四个研究机构，品牌与零售商的首页不在名单里；而「品牌首页当商品页」那条检测只在上下文出现「商品页」时才触发，这里是当「证据」用的，触发不了 |
| 2 | `https://www.cultbeauty.co.uk` 被当作路径对比表的依据 URL | ✅ 属实，同样是裸域名首页，同样是上述两个盲区的交集 |
| 3 | 「东边野兽成立于 2021 年」没有标注出处 | ✅ 属实，而且**这是本轮最有价值的一条**。`briefs/herbeast_uk_v2.json` 里专门写了一段：「成立年份资料有分歧，不要含糊带过：多数中文报道与百度百科写 2020 年；herbeast.world 官方 About 页英文文案写 founded in 2021；BeautyMatter 2026 报道写 (2020)。报告引用成立年份时选一个来源并标注出处，不要两个数字混用」。报告只写了「成立于2021年」没给来源，QA 抓到了——**这需要回查 brief 原文才能判断，是 v6 完全没有做过的动作** |

## 但机械校验抓到了三处 QA 漏掉的问题

`citation_check.py --locale uk` 扫研究三份：31 个 URL，3 处严重问题，全部在 `competitor_battlecard.md`，全部是 QA 没提的：

- Aesop：「公开舆论/口碑线索：Aesop 品牌形象被认可，消费者反馈普遍积极」——无 URL、无「证据不足」
- Weleda：「消费者对其产品天然性及效果评价高，普遍受好评」——同上
- Pai：「在社交媒体和美容博客上有良好口碑，受消费者信赖」——同上

这三条违反 `competitor_analysis.yaml` 要求 6（舆论必须有具体 URL，没有就写「证据不足」）。**QA 的逐 URL 核查表只检查「已经存在的 URL 对不对」，不检查「本该有 URL 的地方是不是空着」**——这是一个方法论层面的盲区，不是模型能力问题。

---

## 两边都漏掉的问题（人工通读发现）

| 问题 | 说明 |
|---|---|
| **Weleda / Pai 用了国际站而非英国站** | 商品页 URL 是 `weleda.com/products/skin-food` 与 `paiskincare.com/products/...`，都不是 `.co.uk`，但标价写的是 £11.25 / £30.00。`competitor_analysis.yaml` 硬规则 4 明确禁止「其他国家/地区站点的商品页」。`--locale uk` 检测没抓到，是因为这两个 URL 路径里根本没有地区码段（检测逻辑依赖路径里出现 `/us/`、`/tw/` 这类片段），QA 也没提 |
| **Aesop 商品页路径里的 `/body/` 疑点** | URL 是 `aesop.com/uk/p/body/aura-restorative-face-cream/`，路径段 `/body/`（身体护理）与产品名 `Face Cream`（面部）对不上。这个疑点从 **v4.1 就被记录过**，跨越 v5、v6、v7 四个版本一直没有人核实过，两套检测也都不覆盖 |

## 客观数据对比

```
                    研究三份机械校验              QA 表现
v6 (gpt-4o-mini)   30 URL / 0 严重 0 警告      2 误报 + 1 自相矛盾 + 真问题 0 命中
v7 (o4-mini)       31 URL / 3 严重 0 警告      0 误报 + 0 自相矛盾 + 真问题 3 命中
```

注意研究三份的严重问题从 0 变成 3，这与 QA 换模型**无关**（研究 agent 模型没变），属于运行波动——v6 那次三家竞品的舆论都老实写了「证据不足」，v7 这次三家都写成了无来源断言。这也再次说明单版本的好坏不能当作规则有效性的证据。

## 对这次实验的诚实解读

**实验回答了它要回答的问题**：v6 的 QA 不可用，主要是**模型能力问题**，不是任务设计问题。同一份 prompt、同一批规则，换成推理模型之后误报和自相矛盾全部消失，还多出了回查原始材料的行为。推理模型「回答前先验证、能自查前后一致性」的特性，与 QA 这类逐条核对任务是对症的。

**但不能因此说 QA 可以替代机械校验**。这一版最有说服力的数据是：QA 抓到 3 件工具漏的，工具抓到 3 件 QA 漏的，两边还都漏了 2 件。三者的分工可以这样理解：

- **机械校验**擅长「穷举式的形式检查」——每一个 URL 的格式、每一个该填 URL 的位置是否空着。它不会漏掉任何一行，但只认它被写进代码的那几种模式
- **QA（推理模型）**擅长「需要回查原始材料的判断」——这个数字 brief 里到底有没有、这个说法有没有出处。它能发现工具没被教过的问题，但不保证覆盖每一行
- **人工通读**目前仍是唯一能发现「国际站冒充英国站」「`/body/` 路径与面霜对不上」这类需要领域常识的问题的方式

**一个方法论层面的收获**：QA 漏掉「舆论无来源」这件事，不是它不够聪明，而是它的任务模板里只有「逐 URL 核查表」——**只检查已存在的 URL，没有一栏是「本该有 URL 却空着的位置」**。这属于任务设计缺陷，换更强的模型也不会自动补上。下一版可以直接在 `qa_review.yaml` 的 `expected_output` 里加这一栏。

## 下一步建议

1. **补机械校验的两个盲区（零成本，优先做）**
   - 「裸域名首页当证据」应当不限于研究机构名单——任何裸域名 URL 出现在「证据」「依据」「URL」列，都该报 warning。这次 Weleda / Cult Beauty 两条都是这么漏掉的
   - 「他国站点」检测目前依赖路径里的地区码段，对 `weleda.com` 这种「国际站主域名、路径无地区码」的情况完全无效。可以改成：当报告声明目标市场是英国时，商品页域名若不是 `.co.uk` 且路径无 `/uk/`，标 warning 让人工确认

2. **给 `qa_review.yaml` 加一栏「应有证据却缺失的位置」**（零成本）
   - 现在的模板只有「逐 URL 核查表」，天然查不到空缺。加一栏专门核对：市场份额、舆论口碑、门槛依据这些**规则要求必须有 URL 的字段**，逐个确认是有 URL 还是老实写了「证据不足」

3. **QA 用推理模型的结论可以写进文档了**
   - `docs/storyline.md` 和 `PROJECT_OVERVIEW.md` 里 QA 的定位可以从「已跑通，准确率不足」升级为「已跑通并验证：在推理模型下可用，与机械校验互补」。但要如实写明它的盲区（不查缺失项）

4. **成立年份这个问题该在 brief 层面解决**
   - QA 抓到了，但每次跑都要靠 QA 抓一遍不划算。可以在 brief 的 `constraints` 里直接加一条硬约束，或者在 `market_feasibility.yaml` 里明确「凡 brief 标注为『资料有分歧』的事实，引用时必须写明选了哪个来源」

5. **成本提示**：o4-mini 是推理模型，思考 token 也计费，QA 这一步的成本会明显高于 mini。但 QA 只跑一次、输入是已生成的报告，绝对成本仍然很低，这个配置建议保留

## 面试怎么一句话讲 v6→v7

> 上一版我第一次把 QA 环节跑通，结果很差——两处误报、自己前后矛盾、真问题一个没抓到。我当时的判断是需要先分清这是模型能力问题还是任务设计问题，所以做了一个单变量实验：只把 QA 这一个 agent 换成推理模型，其他八个 agent 和所有提示词一个字不改。结果三个失败全部消失，而且它抓到了三件我的校验脚本查不到的问题，其中最有意思的一条是：报告写「品牌成立于 2021 年」没标出处，而我的简报里专门写了这个年份在不同来源有分歧、必须标明出处——这需要回查原始材料才能发现，是纯代码校验做不到的。但同一轮里，我的脚本也抓到了三处 QA 完全漏掉的问题。所以我的结论不是「推理模型更好」，而是两者查的是不同类型的问题：代码擅长穷举式的形式检查，推理模型擅长需要回查原始材料的判断。另外我还定位到 QA 漏掉那三处的原因不是模型不够聪明，而是它的输出模板里只有「逐 URL 核查表」，天生只能检查已存在的链接、查不到本该有链接却空着的地方——这是任务设计缺陷，换再强的模型也不会自动补上。
