# 石头科技 v1 — 第三个案例：跨行业压力测试（家电 / 德国）

- **Case**：石头科技 Roborock → 德国，**洗烘一体机 Zeo 系列**（不是它的主力品类扫地机器人）
- **变体**：`research_only`（可行性 → 缺口补证 → 开拓 → 竞品）
- **配套新增**：`briefs/roborock_germany.json`、`knowledge/markets/germany.md`、registry 德国映射
- **本目录**：四份产出 + `tool_audit.jsonl`

## 这个案例是干什么用的

前两个案例（东边野兽→英国、花知晓→泰国）**都是化妆品**。规则里的「成分透明」「品类文化接受度」「商品页判定」等表述其实全是照着美妆写的——就像当初「英国」被写死成字段名一样，这是**行业维度的硬编码**，只有换行业才能暴露。

三个案例的逐级加码：

| | 东边野兽 | 花知晓 | 石头科技 |
|---|---|---|---|
| 行业 | 护肤 | 彩妆 | **家电 / 智能硬件** |
| 市场 | 英国 | 泰国 | **德国**（新知识包） |
| 场景 | 全新进入 | 全新进入 | **已在该市场经营、拓展新品类** |
| 价格量级 | £12–77 | ฿150–500 | **€499–1899** |
| 合规框架 | RP + UK REACH | Thai FDA 通知制 | **CE + EU 能效标签 + WEEE + VerpackG** |
| 竞品性质 | 天然护肤品牌 | 本土 T-beauty | **Bosch / Siemens / Miele 等本土百年白电** |
| 舆论证据源 | 媒体 / 社媒 | 社媒 / 达人 | **Stiftung Warentest 独立测评** |

brief 里埋了两个陷阱，用来测已知的失败模式会不会跨行业复现。

## 最重要的结果：结论第一次降级

```
| 需求匹配     | 0.25 | 3 | 目标市场已有同细分品类产品在售，但证据不足 | 证据不足 |
| 合规可完成性 | 0.15 | 4 | 制度清晰但需完成能效登记                 | 企业网站 |
| 渠道可达     | 0.20 | 3 | 查找到电商平台存在售卖证据，但销量数据缺乏 | 证据不足 |
| 竞争强度     | 0.20 | 3 | 有竞争但预算多且品牌信任度高             | 证据不足 |
| 品牌资产匹配 | 0.20 | 3 | 有些品牌资产可迁移，但需验证             | 证据不足 |

加权总分 = (0.25×3) + (0.15×4) + (0.20×3) + (0.20×3) + (0.20×3) = 3.15
结论：先验证假设、暂缓铺货（加权总分 3.15）
```

**此前 11 个版本、2 个案例，最终结论全部是「建议进入」**——那张评分表从来没影响过结论，是装饰品。这次 3.15 落进 2.5–3.5 区间，模型正确地按规则 8.6 把结论降级为「先验证假设、暂缓铺货」，并在开头一行标注了依据。

一个可行性研究**终于会说「不」了**。这是评分锚点有效性的唯一实证。

需要说明的是：这次能降级，一部分原因是这个案例本身证据更稀薄（德国洗烘一体机品类的公开数据比美妆少），五个维度里四个都只能给 3 分。**锚点是否在证据充分的案例里也能压住分数，还需要更多样本才能确认**——不要只凭这一次就说锚点一定有效。

## 两个设计陷阱：都没踩中

### 陷阱一：美妆硬编码 —— 零残留

全文 grep「成分 / 草本 / 护肤 / 精华 / 面霜 / 品类文化接受度」，**四份产出一个都没有**。

这说明之前为修「英国」硬编码所做的泛化（把字段名从具体国家改成「目标市场」、把品类相关表述改成由 brief 决定）**经受住了跨行业检验**。当初那次修的不只是一个国名，而是一整类"模板写死"的问题。

### 陷阱二：品牌资产迁移 —— 没被误用

brief 里明确警告过：石头科技在德国扫地机器人品类 GMV 市占 34.4%（公开报道），但**这不能推出洗衣机品类有优势**——对手是 Bosch/Siemens/Miele 这些在德国经营上百年的本土白电品牌。

报告的处理是对的：

```
| 品牌资产匹配 | 0.20 | 3 | 有些品牌资产可迁移，但需验证 | 证据不足 |
```

打 3 分、标「需验证」、证据栏写「证据不足」，**没有把原品类的市场地位当成新品类的优势证据**。正文里也只是陈述「已成功进入扫地机器人品类，正在拓展洗烘一体机」这个事实，没有做因果推断。

## guardrail 软上限：修好了一个我自己引入的静默失败

### 先说这一轮之前踩的坑

**第一次跑石头科技时，竞品 task 失败了，但失败得毫无声息。**归档出来的 `competitor_battlecard.md` 打开一看写的是 Mistine、Cathy Doll、Srichand——**上一轮花知晓的泰国彩妆内容，逐字节相同**。

根因链条：guardrail 重试耗尽 → CrewAI 抛异常中断 → 该 task 的 callback 不触发 → 输出文件不更新 → **上一次运行的旧文件原样留在磁盘上** → `cp` 归档时把它当成了本轮产出。

这个 bug 是我在改「用 callback 写文件」时引入的，而且比它修掉的那个问题更隐蔽：**原来是 guardrail 白跑，现在是整个 task 消失但看起来一切正常**。

### 修了两处

1. **guardrail 加软上限**：重试达到上限后**放行**，但在产出顶部插入醒目失败标记，而不是让 CrewAI 抛异常中断流水线。本轮实测生效，竞品报告顶部有：

   > ⚠️ **本文未通过引用校验，且已达到自动重试上限**（2 次）。以下内容仍存在 1 处严重问题，**不可直接当成品交付**，需人工修改。

   **问题留在文件里被后续检查和人看见，比让整条链路猝死好。**

2. **加产出完整性检查**：跑完自动比对每个输出文件的 mtime 与本轮开跑时间，未更新的直接大声报出来并警告"不要直接 cp 归档"。

**可复用的教训**：给流水线加自动重试时，必须同时想清楚「重试耗尽之后怎么办」——框架默认的「抛异常中断」在批处理场景里是最差的选择。

## 老问题第三次复现：工具用了，但不看结果

这一轮抓取工具**第一次被大量真实使用**：9 次 `read_website_content`，而且抓的是竞品商品页而非首页。但把审计日志与独立 HTTP 验证对照：

| 报告写的 URL | 模型抓取时实际收到 | 独立验证 |
|---|---|---|
| `bosch-home.com/de/shop/Waschmaschine/WDU28560EU` | **48 字符** | **404** |
| `siemens-home.bsh-group.com/de/shop/Waschmaschine/WT47W5W0` | 11689 字符（应为 404 页面的 HTML） | **404** |
| `aeg.com/de/shop/.../waschtrockner-l8wbe961/` | 691 字符 | 200，但页面上找不到报告写的 €1,399 |
| `miele.de` | 297 字符 | 403 |
| `amazon.de/.../dp/B0F3XGCS8H` | **41121 字符**（真实商品页） | — |

**模型抓了页面、收到了 48 字符的空内容或错误页，照样把 URL 和标价写进了报告。**

这与之前两次是同一个病：
- agentic 实验：抓到 106 字符的 Cloudflare 拦截页，写「已核实，页面显示标价 £34.00」
- 东边野兽 guardrail_trial：凭记忆拼 URL，5 条里 3 条 404

**三次复现说明这不是偶发，是稳定的行为模式：模型把「调用过工具」等同于「完成了核实」，从不检查返回内容是否有效。**

唯一的好消息是 Amazon.de 那条抓回了 41121 字符的真实商品页——**说明当来源站点不反爬时，工具链是通的**，问题在模型的验证意识而非工具能力。

## 事后修复：严重问题 5 → 1（其中 4 处是我自己的检测有问题）

初检报 5 处严重。逐条查下来，**只有 1 处是真的**，另外 4 处是检测器的毛病。这一段记录修的过程，因为「误报」比「漏报」更值得写——漏报只是没帮上忙，误报会让人不再信任这个工具。

### 误报 A（3 处）：把「诚实声明」当成了「推诿」

`evidence_gap_fill.md` 里：

```
- 新事实：未找到Stiftung Warentest对Zeo系列的评测信息。 | URL: 未找到 | 级别 N/A
```

这**正是 brief 要求的表述**——查不到就写未找到，禁止编造评级，模型照做了。但「级别 N/A」触发了「TBD 占位符代替证据」检测。

根因是我把 `TBD` 和 `N/A` 放进了同一个模式表，而它们语义相反：

| | 含义 | 该不该拦 |
|---|---|---|
| **推诿型**：TBD / 待补充 / 待更新 / 待定 | 承诺「以后会有」，把空白伪装成待办 | **无条件拦** |
| **声明型**：N/A / 不适用 | 声明「这里本来就没有」 | **只在没诚实说明缺失时拦** |

修法：拆成两类。推诿型照旧无条件拦；声明型只有当该行**没有**「证据不足 / 未找到 / 无法核实」这类诚实说明时才拦。

这不会开出漏洞：「有数字却没来源」由数字关独立负责，而那一关明确规定加免责词不豁免。两关职责分明。

回归验证：全归档 13 个版本扫描，新规则只放过了这 3 行，其余版本一处未变；`backup_v3` 里那个真正的 TBD 仍被抓到。

### 误报 B（1 处）：guardrail 的失败标记在自我指认

guardrail 重试耗尽时会在文首插入一段引用块，逐条列出没修好的问题：

```
> ⚠️ **本文未通过引用校验，且已达到自动重试上限**（2 次）
> - 【品牌首页当商品页】https://www.miele.de 是裸域名首页，没有具体商品路径
```

**下一次校验读到这段话，把里面引用的 `miele.de` 当成一条新的违规重新报了一遍。**同一个问题被数了两次。

这是「检测器读到了自己的输出」这类污染。修法是校验前先剥掉标记块。

**可复用的教训**：任何**把检查结果写回被检查对象**的设计，都必须同时保证下一轮检查能认出并排除这段自我描述——否则指标会自我膨胀，而且是单调递增的那种。

### 顺带修好：德国根本没进 locale 映射

`_locale_from_scope("德国")` 返回空串，于是「他国站点当本地商品页」这项检测**在整个石头科技那轮被静默跳过了**。加上 `germany / 德国 / deutschland` 后补跑，这一项确实没有新增违规——但**在此之前它是没跑的，"没报错"不等于"查过了"**。

关键词刻意只用完整词，没有用 `de`：匹配是子串比对，`de` 会误命中 `sweden`、`denmark`、`bangladesh`。**漏判只是跳过一项检测，误判会让整份报告被按错误地区校验——宁可漏不可错。**

### 剩下的 1 处是真的

竞品报告里 Miele 那条：`本地货币标价：€1,899`，商品页 URL 写「未找到」，只给了 miele.de 首页当搜索线索。价格是硬数字，必须有来源，这条 guardrail 重试 2 次没修好，已按软上限设计放行并加标记。

## 顺带发现的检测盲区（已确认范围，暂不修）

上面那条 Miele 之所以被抓到，是因为那一行**碰巧带了个 miele.de 链接**。如果写成：

```
- 本地货币标价：€1,899
- 商品页 URL：未找到
```

**数字关是逐行判的，价格和「未找到」在不同行，这个无源价格就查不出来。**

扫了全部归档确认影响范围：**9 处，全部在早期版本**（`backup_v1`、`agentic_v1`、`agentic_v2`），因为那时用 bullet 格式；现行规则强制表格，价格与依据在同一行，逐行判定成立。**当前案例不受影响。**

一个必须如实说明的副作用：**agentic 那两版当初显得「引用问题不算多」，一部分原因是它的 bullet 格式绕开了逐行检测。**这不推翻「agentic 版通常更差」的结论——它只说明**差距被低估了**，agentic 实际比测出来的还要差。但这提醒我：**当被测对象能改变输出格式时，格式本身就成了规避手段**，指标可比性会被悄悄破坏。

暂不修的理由：需要把检测从「逐行」改成「逐块」（把一个 bullet 条目视为整体），改动面比收益大，且现行格式规则已经堵住。**记账，不假装不存在。**

## 由本轮引出的最大发现：评分表连算术都是错的

给锚点做机械校验时，我顺手写了个脚本把每份报告的加权式子**重算一遍**，再核对结论档位。结果远超预期：

**12 个带评分表的归档版本，9 个把自己的加权总分算错了，其中 5 个的结论与它自己写的分数矛盾。**

| 版本 | 报告写 | 实际 | 问题 |
|---|---|---|---|
| 东边野兽 backup_v3 | 3.4 | 3.45 | 算错 + 结论矛盾 |
| 东边野兽 backup_v4.1 | 3.75 | 3.8 | 算错 |
| 东边野兽 backup_v5 | 3.15 | 3.25 | 算错 + 结论矛盾 |
| 东边野兽 backup_v6 | 3.15 | 3.25 | 算错 + 结论矛盾 |
| 东边野兽 backup_v7 | 3.55 | 3.6 | 算错 |
| 东边野兽 backup_v8 | **3.35** | **3.65** | 算错 + 结论矛盾 |
| 东边野兽 guardrail_trial | 3.35 | 3.45 | 算错 + 结论矛盾 |
| 花知晓 backup_v4 | 3.55 | 3.65 | 算错 |
| 花知晓 backup_v5 | 3.55 | 3.8 | 算错 |
| 花知晓 v1 | 3.65 | 3.65 | ✅ |
| **石头科技 v1** | **3.15** | **3.15** | **✅ 唯一四项全过** |

东边野兽 v8 最典型：

```
报告写的：Σ(权重×得分) = 0.25×4 + 0.15×3 + 0.20×3 + 0.20×4 + 0.20×4 = 3.35
实际算：                                                          = 3.65
报告的结论：建议进入
按它自己写的 3.35，规则 8.6 要求的是：先验证假设、暂缓铺货
```

**这说明分数和结论根本是各写各的**：模型先定下想说的结论，再产出一段看起来很像回事的计算，中间没有任何一步检查两者是否一致。

**这比假引用更隐蔽**：假引用还需要读者点开链接才知道是假的；算错的加权和**连点都不用点，但也恰恰因此没人会去验**——它长得太像已经被验过的样子了。

**已修**：新增 `src/marketing_crew/scoring_check.py`，四项检查（权重和是否为 1 / 算术 / 结论档位与总分一致 / 得分是否在 1–5），已接入主流程，`--strict-citations` 下会中断。

**这也补上了发现五的另一半**：锚点约束了「每一维打几分」，但此前没有任何东西约束「这些分怎么汇总成结论」。现在两头都有了。

## 冻结状态

**本版不作为展示版**，理由：竞品报告顶部带 guardrail 失败标记、深度门禁 4 处严重、Miele 那条无源价格未修好。

展示版仍是 `outputs/花知晓/backup_v4/` 与 `outputs/东边野兽/backup_v8/`。

**注意**：本目录的四份 md 是**修检测器之前**产出的，内容未改；上面「5 → 1」是用修好后的检测器复检同一批文件得到的结果，**不是重跑**。所以文件里那三行 `级别 N/A` 仍在——它们本来就是对的，是检测器之前判错了。

本版作为**第三案例的首测记录**存档，价值在于：跨行业泛化验证、评分锚点首次改变结论、以及暴露出的四个检测器缺陷。

## 面试怎么讲这一枪

> 我做完两个化妆品案例之后意识到一个风险：我那些规则里的「成分透明」「品类接受度」，
> 跟当初写死的「英国」是同一类问题——**行业维度的硬编码**，只在同行业里永远不会暴露。
> 所以我做了第三个案例，故意跨到家电行业：石头科技的洗烘一体机进德国，
> 对手是 Bosch、Miele 这些本土百年白电，合规框架从化妆品备案变成 CE + 能效标签 + WEEE。
>
> 结果有两个。一是美妆硬编码**零残留**——之前那次泛化改的不只是一个国名，
