# 花知晓 v2 提升日志（相对 v1）—— 泰国案例首次跑 QA

- **Case**：花知晓 / Flower Knows → 泰国（彩妆）
- **变体**：`research_qa`（可行性 + 开拓 + 竞品 + QA）。**这是泰国案例第一次跑 QA**，v1 只跑了 `research_only`
- **模型**：QA 用推理模型 `o4-mini`，其余 8 个 agent 用 `.env` 的 `gpt-4o-mini`
- **v1 → v2 之间改了什么**：修了模板硬编码「英国」的 bug、给三个 task 加了禁 TBD/商品页收紧/首页不得给高置信度等规则、给 QA 加了「应有证据却缺失」与「与 brief 不符」两栏、机械校验从 5 类检测扩到 13 类
- **对比方式**：QA 输出逐条回查配置原文与 `briefs/flowerknows_thailand.json`；研究三份跑 `citation_check.py --locale th`

---

## 一句话

QA 在这个案例上立了一次大功——抓到一处**纯代码永远查不到的过度推断幻觉**（把「泰国在国际化布局名单里」写成了「已按计划扩展至泰国市场」）。但同一份 QA 报告里也暴露了两个新问题：**同一个 URL 在两张表里判定相反**，以及**「已写证据不足」判得太浅**（「约 25%（证据不足）」被判合规，而机械校验正确判为违规）。两个问题本轮都已针对性修复。

## QA 的最大贡献：抓到一处过度推断幻觉

报告原文（`market_feasibility.md` 品牌—市场匹配一节）：

> **国际化策略明显**：该品牌CMO已明确指出国际化扩张为"主要焦点"，**表明已按计划扩展至泰国市场**

回查 `briefs/flowerknows_thailand.json` 原文，brief 里只写了：CMO 表示国际化是「major focus」、过去一年国际业务增长超 200%、品牌已布局的市场列表包含泰国。**从来没有说"已按计划扩展至泰国"**——「在布局名单里」和「已经按计划扩展进去了」是两件事。

QA 在新加的「与 brief 不符或无出处的事实清单」栏里准确判定为「**brief 中不存在**」，并给出了修改建议（改成"CMO 表示泰国为主要拓展目标，具体合作形式待核实"）。

**这类问题机械校验在设计上就查不到**：这句话有 URL、格式完美、语法通顺，唯一的问题是从证据到结论多跨了一步。这直接证明了新增那一栏的价值。

## 但 QA 自己出了两个新问题

### 问题一：同一个 URL 在两张表里判定相反

| 位置 | 对 `facebook.com/mistine` 的判定 |
|---|---|
| 「逐 URL 核查表」第 19 行 | 首页证据，需要换成具体页面 → **不通过** |
| 「应有证据却缺失」第 34 行 | 有 URL → **合规** |

三家竞品的社媒链接都是这个情况（Mistine 的 Facebook、Cathy Doll 的 Instagram、Srichand 的 Twitter）。说明 QA 填两张表时是**分开推理的，没有交叉对照**。

这是 v6 那个"列了阻塞问题却全打勾"的自相矛盾的**变种**——形式不同，本质一样：同一份输出内部前后不一致。上一轮加的约束只覆盖了"检查清单 vs 阻塞问题"，没覆盖"表格 vs 表格"。

### 问题二：「已写证据不足」判得太浅

三家竞品的市场份额分别写着「约 25%（证据不足）」「约 18%（证据不足）」「约 15%（证据不足）」。

- **QA 判定**：已写证据不足 → 合规 ✅
- **机械校验判定**：无来源数字 → 违规 ❌

**机械校验是对的。**给了具体百分比却没有任何来源，后面加个免责词——这正是花知晓 v1 就识别出来的规避写法，当时还专门为它加了「兜底措辞不豁免」检测。QA 看到"证据不足"四个字就通过了，**没注意到前面挂着个数字**。

也就是说：新加的反向核查栏虽然填了，但是**模式匹配式地填**，不是真的核对。

---

## 两边都漏的：社媒账号主页当舆论证据

三家竞品的「公开舆论/口碑线索」引用的分别是：

- `facebook.com/mistine`
- `instagram.com/cathydolland`
- `twitter.com/srichand`

**全是品牌自己的账号主页。**品牌自营账号证明不了公众口碑——这跟"拿品牌官网首页证明产品好卖"是同一类错误。

- 机械校验当时没抓到：这些 URL 有路径（`/mistine`），不算裸域名，旧检测覆盖不到
- QA 在「逐 URL 核查表」抓到了，但在「反向核查栏」又放过了（见上面问题一）

---

## 本轮据此做的三处修复

| 修复 | 位置 | 内容 |
|---|---|---|
| 新增「社媒账号页当舆论证据」检测 | `citation_check.py` | 舆论字段引用社媒域名且路径深度 ≤1（账号主页而非具体帖子）时报 error。六个正反用例全过，含"具体帖子页不应报""测评文章不应报"等反例 |
| QA 加规则 7.5「判定证据不足前先看有没有数字」 | `qa_review.yaml` | 明确写"证据不足只对不含数字的定性描述有效"，并把「约 25%（证据不足）」这个具体反例写进规则 |
| QA 加「交叉一致性自查」段 | `qa_review.yaml` | 输出前必须核对三件事：同一 URL 在不同表格的判定一致、检查清单勾选与阻塞问题一致、"已写证据不足"先过数字关 |

另加了规则 7.6，明确舆论证据必须是具体帖子/评论/第三方测评，不能是账号主页。

## 对这一版的诚实解读

这一版把「QA 与机械校验互补」这个结论推进了一层：**它们不只是覆盖面互补，还会在同一件事上给出相反判断，而且不一定谁对**。

- 「约 25%（证据不足）」这条，**机械校验对、QA 错**——因为这条规则可以被精确定义（含数字就必须有 URL），代码执行得更可靠
- 「表明已按计划扩展至泰国」这条，**QA 对、机械校验根本没意见**——因为这需要理解"布局名单"和"已扩展"的语义差别，代码做不到

所以不存在"以谁为准"，而是**要按问题类型分工**：能精确定义的规则交给代码，需要语义判断的交给模型，两边都要人工抽查。

另一个观察：QA 的失败模式在**演化**，跟模型的规避行为一样。v6 是"列了阻塞却全打勾"，加了约束之后，v2 变成"同一 URL 在两张表里判定相反"。都是内部不一致，但表现形式换了。这提示后续给 QA 加约束时，与其逐个堵具体形式，不如直接要求"输出前做一次全文交叉核对"——本轮的修复就是按这个思路写的。

## 面试怎么一句话讲花知晓 v1→v2

> 这是泰国这个案例第一次跑 QA 审校。最有价值的发现是 QA 抓到了一处纯代码永远查不到的问题：报告写「品牌已按计划扩展至泰国市场」，但我的简报里只说泰国在国际化布局名单里，从没说已经扩展进去了——这句话有链接、格式完美，唯一的问题是从证据到结论多跨了一步。但同一份 QA 报告里我也发现了两个新问题：同一个链接在两张表里被判成相反结论，以及它把「市场份额约 25%（证据不足）」判成合规——而我的脚本正确地判成违规，因为给了没来源的数字再加免责词，正是我们之前专门为之写过检测的规避写法。所以我的结论是，QA 和机械校验不只是覆盖面互补，还会在同一件事上给出相反判断——能精确定义的规则交给代码更可靠，需要语义判断的交给模型，两边都要人工抽查。
