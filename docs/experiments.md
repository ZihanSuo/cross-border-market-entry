# 第一部分：已实际跑过的评估

## 1. 跨版本规则遵守率矩阵

**做什么**：用**当前**的 18 类检测规则，回溯扫描全部 33 个归档版本（东边野兽 16 个 + 花知晓 13 个 + 石头科技 4 个），输出「版本 × 问题类型」矩阵。

> 两个 `agentic_*` 目录不在矩阵里——它们的产出文件名是 `competitor_battlecard_agentic.md`，
> 与标准四份不同，刻意不混进主线对比（agentic 是对照分支，见下方实验三）。

**为什么需要**：之前每次都是「跑一版 → 人工通读 → 工具扫一遍 → 写 changelog」，结论散在十几份 changelog 里，没法回答「假域名到底是稳定消失了还是运气好」这类跨版本问题。

**怎么跑**（零 API 成本，几秒钟）：

```bash
PYTHONPATH=. python experiments/rule_compliance_matrix.py            # 终端表格 + 自动结论
PYTHONPATH=. python experiments/rule_compliance_matrix.py --markdown # markdown，可直接贴文档
```

### 结果（2026-08-12）

#### 东边野兽 → 英国（护肤）

| 版本 | URL 数 | 严重 | 警告 | 密度 | 主要问题 |
|---|---|---|---|---|---|
| backup_v1 | 0 | 0 | 0 | 0.0 | ⚠ 全文零引用（**不等于干净**，见下方注解） |
| backup_v2 | 24 | 0 | 7 | 0.0 | 裸域名×7 |
| backup_v3 | 28 | 8 | 12 | 2.9 | 假域名×4、未填模板×1、TBD×1、国际站×3 |
| backup_v4 | 35 | 1 | 25 | 0.3 | 品牌首页×1、分类页×13、裸域名×11 |
| backup_v4.1 | 36 | 0 | 10 | 0.0 | 分类页×2、参考退化×3 |
| backup_v5 | 24 | 2 | 5 | 0.8 | 舆论无源×2 |
| backup_v6 | 30 | 0 | 2 | 0.0 | 国际站×1 |
| backup_v7 | 31 | 4 | 5 | 1.3 | 舆论无源×3、国际站×2 |
| **backup_v8**（冻结） | 36 | 1 | 6 | 0.3 | 国际站×2、裸域名×4；1 严重 = SKU 与 URL 品类矛盾 |

#### 花知晓 → 泰国（彩妆）

| 版本 | URL 数 | 严重 | 警告 | 密度 | 主要问题 |
|---|---|---|---|---|---|
| v1 | 39 | 15 | 21 | 3.8 | 品牌首页×5、无源数字×5、舆论无源×5、国际站×4 |
| v2 | 36 | 7 | 9 | 1.9 | 无源数字×3、社媒主页×3、品牌首页×1 |
| backup_v3 | 21 | 0 | 3 | 0.0 | 分类页×2 |
| **backup_v4**（冻结） | 37 | 0 | 3 | 0.0 | 国际站×2 |

密度 = 每 10 个 URL 的严重问题数，用于抵消报告长短差异。

### 三行结论

1. **假域名（编造引用）确实被根治了**：只出现在 backup_v3（4 处），此后 9 个版本全部为 0。这是唯一能说「稳定消失」的一类问题。
2. **花知晓案例的改善幅度最大**：严重问题从 v1 的 15 处降到 backup_v3/v4 的 0 处，密度从 3.8 降到 0.0。但注意 v1→v2 的数字**不能直接比**——期间新增了「社媒账号页当舆论证据」等检测，检测集合本身在变。
3. **同配置重跑会有明显波动**：v6（0 严重）→ v7（4 严重）是同一份 prompt 的两次独立运行。**这条是本项目决定「冻结版本、不再重跑」的直接依据**——重跑赌更好结果的期望收益为负。

### 两个必须注明的读法

**「0 个 URL」不是干净，是最坏。** backup_v1 全文 262 行、零引用，机械扫描显示"零问题"，但那说明当时压根没有引用纪律。脚本已特判标注为「⚠ 全文零引用」。**这是评估体系设计里很典型的陷阱：指标为 0 可能是最好，也可能是最坏。**

**数字会随规则演进而变化，且不回头粉饰。** backup_v8 在跑的当天校验是 0 严重，现在显示 1 严重——多出来的是后来新增的「SKU 名与 URL 品类矛盾」检测回溯抓到的（一条 Aesop 商品页 URL 路径写着 `/body/` 但 SKU 名是面部产品）。这个问题从 v4.1 起跨了五个版本没被发现。两个数字都保留：当天的 0 反映当时的检测能力，现在的 1 反映检测能力的进步。

## 2. QA 审校召回率 Benchmark

**做什么**：拿已归档的报告当**固定输入**喂给 QA 环节，用人工标注的已知问题清单算召回率。

**为什么需要**：验证 QA 改动的唯一办法本来是跑一整轮 `research_qa`——花钱、慢、而且每次输入都不一样（研究报告会重新生成），不是干净对照。这个 benchmark 让 QA 直接读归档报告，跳过研究三步：几毛钱、几十秒、输入完全一致。

**测试集**：`experiments/qa_bench_cases.yaml`，3 个 case、18 条人工确认过的已知问题。每条标注了 `detectable_by`：

- `tool` = 机械校验能抓（QA 曾漏掉的，**这几条才是真考验**）
- `qa` = 只有语义判断能抓（QA 的价值所在）
- `neither` = 两者都抓不到（记录覆盖边界）

**怎么跑**：

```bash
PYTHONPATH=. python experiments/qa_bench.py --all              # 跑全部 case
PYTHONPATH=. python experiments/qa_bench.py --all --repeat 3   # 跑 3 次看稳定性
PYTHONPATH=. python experiments/qa_bench.py --case herbeast_v8 --dry-run  # 只看 prompt，免费
```

### 结果（o4-mini，2026-08-11）

| Case | 召回 | 说明 |
|---|---|---|
| herbeast_v3 | 3/3（100%） | 回归基线：最基础的假域名/未填模板/机构首页全部抓到，说明改动没把 QA 改坏 |
| herbeast_v8 | 5/7（71%） | 漏 1 条波动性的（绝对化用词）、1 条三层都覆盖不了的（URL 路径与品类矛盾） |
| flowerknows_v2 | 8/8（100%） | 本轮新规则的目标全部命中 |

### 两条关键发现

**规则改写有效，而且是可验证的因果**：flowerknows_v2 里三条「市场份额约 25%（证据不足）」，上一版 QA 判为"已写证据不足、合规"，加了规则 7.5（判定前先看有没有数字）之后，QA 的判定变成「**违规：含数字无 URL**」——措辞与新规则完全对应。同理，「已按计划扩展至泰国市场」这条过度推断，在规则 8 改写成三分类（事实/推断/分歧）之后才被抓到，QA 明确按「推断」这一类填表并判「推断超出原文」。

**同配置多次运行结果不同**：herbeast_v8 的「消费者评价极高」这条，第一轮抓到、第二轮没抓到。所以单次数字有噪声，判断改动是否有效时可能被波动淹没——这是加 `--repeat` 的原因。逐条稳定性会标注为「稳定命中 / 稳定漏掉 / **不稳定**」三态。

### 评分口径的局限（重要）

命中判定是**关键词匹配**，是粗糙近似。踩过两次假阳性的坑，都记在标注文件里：

1. 最初用品牌名当匹配键 → 一提到 "Srichand" 就把它名下三条不同问题全判成命中，召回率从真实的 38% 虚高到 75%
2. 改用 `/body/` 这类特征片段后仍假阳性 → 因为这些片段**本身就在 URL 里**，QA 只要引用了那条 URL 就会匹配上，**但引用 URL ≠ 指出问题**（它实际把那条判成了"正常"）

最终解法：加 `match_in_prose_only` 开关，匹配前先把 URL 整体挖掉。**这个数字适合同一套标注下的纵向对比，不宜当作 QA 的绝对能力值。**

## 3. 两组对照实验

### 实验一：换案例 —— 测规则是通用还是过拟合

**设计**：前五轮都在东边野兽（护肤/英国）上调规则，每版都更好看，但分不清「规则有用」还是「规则被调得刚好适配这一个案例」。于是换一个差异尽量大的案例：花知晓、彩妆、泰国，品类和市场同时更换，配套写了泰国市场知识包。

**结果**：第一次跑，整份泰国竞品分析里四家泰国本土品牌每家都写着「**英国**市场份额」「**英国**渠道线索」。根因是把「英国」当成**字段名**写死进了模板。

**关键点**：这个 bug 在原案例下**永远正确、永远不报错**。

**结论**：规则分两类，迁移能力完全不同——**语义类规则**（如「证据不足的结论不能在后文变成确定结论」）跨案例迁移得很好；**模板类规则**（字段名、制度名称、货币符号）严重过拟合，换场景就崩。

### 实验二：换模型 —— 分清模型能力缺口还是任务设计缺陷

**设计（严格单变量）**：QA 首次跑通时表现很差（两处误报、自相矛盾、真问题零命中）。判断需要先分清是模型能力问题还是任务设计问题，所以**只把 QA 这一个 agent** 从 `gpt-4o-mini` 换成推理模型 `o4-mini`，其余 8 个 agent 和全部 4 份 prompt 一字不改。

**结果**：

| | 研究三份机械校验 | QA 表现 |
|---|---|---|
| v6（gpt-4o-mini） | 30 URL / 0 严重 | 2 误报 + 1 自相矛盾 + 真问题 **0 命中** |
| v7（o4-mini） | 31 URL / 3 严重 | 0 误报 + 0 自相矛盾 + 真问题 **3 命中** |

**结论**：不是「推理模型更好」这么简单——**三者查的是不同类型的问题**。QA 抓到 3 件工具查不到的（引用无出处、与 brief 原文不符），工具抓到 3 件 QA 漏掉的（本该有 URL 却空着），两边还都漏了 2 件（需要真打开网页才能验证的）。

**更关键的归因**：QA 漏掉那 3 处的根因**不是模型不够聪明**，而是输出模板里只有「逐 URL 核查表」，天生只能检查已存在的链接、查不到本该有链接却空着的地方。**这是任务设计缺陷，换再强的模型也不会自动补上**——加了反向核查栏之后，v8 验证确实生效了。

### 实验三：Workflow vs Agentic（保留的失败实验）

把最独立的一步（竞品分析）改成自主研究模式：给目标不给模板、加网页抓取工具、自己决定查几家/深挖谁/何时停。跑了 4 轮，产出质量**稳定低于模板版**（21 URL / 7 严重 vs 模板版 36 URL / 1 严重）。

失败模式的演化才是价值所在：

| 轮次 | 改动 | 失败形式 |
|---|---|---|
| 1 | 放开输出模板 | **0 个 URL**，必需章节全缺 |
| 2 | 结构约束改回硬性 | 结构恢复，但**伪造核实记录**（10 条声明，对质通过 0 条） |
| 3 | 加工具调用审计 | 审计证明**确实调用了 6 次抓取且全部成功**，但抓的是品牌首页和反爬拦截页（106 字符），照样写"已核实" |
| 4 | 删掉「核实状态」自述栏 | 出现第一条诚实记录，但把 4 个网站首页标成「单品页」 |

**可迁移结论**：只要设计里留了「让模型报告自己做得怎么样」的字段，它就会填出好看但不真实的内容。**执行状态的判定必须交给代码**——这就是 `tool_audit.py` + `verify_claims.py` 存在的理由。

完整记录见 `outputs/东边野兽/agentic_v2/CHANGELOG.md`。

# 第二部分：Ablation 框架（**近期未重跑**）

> ⚠️ **与当前项目定位不一致，重跑前需先对齐基准。**
> 下面的变体定义（含策略/内容/QA 全流水线）是早期口径；当前 V1 已收窄为「可行性 → 缺口补证 → 开拓 → 竞品」。
> 指标里的 `channel_adaptation_score`（小红书/抖音术语覆盖）也已不适用于研究链路。
> 直接重跑会得到与现在讲的故事对不上的数字。

## 实验目标（原始设计）

1. 多 Agent 是否优于单 Agent
2. 市场/竞品研究阶段是否提供增益
3. QA 审校节点是否提升输出可靠性

## 实验变体（原始设计）

- `single_agent`：仅执行单任务策略生成
- `no_research_stage`：不执行市场研究与竞品分析
- `no_qa`：不执行最终 QA 审校
- `full`：完整链路（研究 → 策略 → 内容 → QA）

## 指标定义

来自 `experiments/evaluate_outputs.py`：

- `structure_completeness` —— 关键结构字段覆盖程度
- `traceability_score` —— 结论中来源/链接的覆盖程度。**注意**：早期版本只数 `https://` 出现次数，`example.com` 也计满分；现已改为扣掉假引用后的真实可追溯率（`citation_validity_score`）
- `channel_adaptation_score` —— 小红书/抖音术语覆盖（**研究链路不适用**）
- `elapsed_sec` —— 运行耗时

## 运行方式

```bash
PYTHONPATH=. python experiments/run_ablation.py
```

生成 `outputs/ablation_report.json` 与 `outputs/ablation/<variant>/*.md`。

## 若要重启这条线，需要先做

1. 把变体重新定义到研究链路本身（例如 `no_gap_fill` vs `research_only`，测缺口补证这一步的增益）
2. 去掉 `channel_adaptation_score`，换成与研究质量相关的指标（可复用 `citation_check` 的 18 类检测密度）
3. 考虑多次运行取均值——本项目已实测同配置重跑波动明显，单次 ablation 结果不可靠
