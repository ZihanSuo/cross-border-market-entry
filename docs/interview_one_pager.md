# 项目一页纸

更细：`docs/storyline.md` · Depth 收口：`docs/depth_v1_honest_summary.md` · 演示包：`outputs/README.md`

---

## 30 秒

我做了一个帮中国品牌做出海市场研究的多 Agent 系统（可行性 → 补证 → 开拓 → 竞品）。提示词里写了二十多条硬规则，模型还是会编造引用、算错加权分。所以我加了**不依赖模型自评的代码校验**，并把「做得对不对」做成 guardrail 裁判。

为了证明规则不是只适配一个案例，我换了品类和市场，又换了行业——第三个案例石头科技进德国，评分锚点第一次让系统算出 3.15、说了「先验证假设、暂缓铺货」。**会说 no，比报告好看更重要。**

---

## 2 分钟（推荐）

1. **问题**：单 Agent 研究缺来源、规则不遵守、结论只会「建议进入」。  
2. **做法**：CrewAI 上 SOP 式三角色流水线 + 引用/评分/产物地板的机械校验；agentic 竞品对照跑过四轮，败在「自我报告已核实」。  
3. **泛化**：花知晓泰国暴露「英国」写死进模板；工具自己的盲区曾把基线严重数报少三分之二。  
4. **行为改变**：给五维评分写 1/3/5 锚点 + 总分锁档位 → 石头德国案首次降级。  
5. **Depth**：后来加了证据地板变体——流水线能通，soft-pass 横幅明确不当成品；**更深的模板没有自动带来更诚实的结论。**  
6. **卖点定位**：卖的是「约束研究 Workflow + 可复利的评测闸 + 诚实失败对照」，不是「自动化麦肯锡」。

## 三个快问快答

| 问 | 答 |
|---|---|
| Agent vs Workflow？ | 差在控制流让渡多少；「下一步做什么」可让，「这步对不对」必须代码判。 |
| 怎么评估？ | 引用密度、评分重算、工具审计对质、QA benchmark；并讲清指标何时骗人（零引用、匹配键）。 |
| 深度不够？ | Depth = 地板 + 诚实 soft-pass；咨询深度仍要人。说 no 靠锚点，不靠更深 prompt。 |
