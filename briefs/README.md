# Brief 填写说明（V1：市场 + 竞品）

V1 **只做市场研究与竞品分析**。默认：品牌方已有探索进入意向 → 报告重点是 **进入条件 / 就绪度 / 本地化优先级**，不是戏剧性空 Yes/No。

| `briefs/herbeast_uk_v2.json` | **对照基线**：东边野兽 → 英国（护肤，第一个案例），公开资料最厚、版本最多（v1–v8） | [`outputs/东边野兽/backup_v8/`](../outputs/东边野兽/backup_v8/) |
| `briefs/roborock_germany.json` | **跨行业压力测试**：石头科技 → 德国（**家电**，洗烘一体机品类）。配套 `knowledge/markets/germany.md` | [`outputs/石头科技/v1/`](../outputs/石头科技/v1/)（未冻结） |

## 三个案例是怎么逐级加码的

| | 东边野兽 | 花知晓 | 石头科技 |
|---|---|---|---|
| 行业 | 护肤 | 彩妆 | **家电 / 智能硬件** |
| 市场 | 英国 | 泰国 | **德国** |
| 场景 | 全新进入 | 全新进入 | **已进入该市场、拓展新品类** |
| 价格量级 | £12–77 | ฿150–500 | **€499–1499** |
| 合规框架 | RP + UK REACH | Thai FDA 通知制 | **CE + 能效标签 + WEEE** |
| 竞品性质 | 天然护肤品牌 | 本土 T-beauty | **Bosch/Miele 等本土百年白电** |
| 舆论证据源 | 媒体/社媒 | 社媒/达人 | **Stiftung Warentest 独立测评** |
| 主体 | 非上市 | 非上市 | **A 股上市（688169.SH），有公开财报** |

**第三个案例专门用来暴露美妆硬编码**：前两个案例都是化妆品，规则里的「成分透明」「品类文化接受度」「商品页判定」等表述都是照着美妆写的。家电这一套里没有「成分」只有「参数与能效」，合规也完全不同。brief 的 `constraints` 里专门写了一条：**若报告中出现「成分」「草本」「护肤」等与本品类无关的维度，说明配置里有美妆硬编码，应视为缺陷记录下来。**

它还引入了一个前两案例没有的结构：**品牌已在德国是扫地机器人市占第一，但洗衣机是全新品类**——考验报告会不会错误地把原品类的市场地位当作新品类的优势证据。

**为什么要多个案例**：前五轮都在东边野兽上调规则，每版都比上版好看，但分不清「规则真的有用」
还是「规则只是被调得刚好适配这一个案例」。换成花知晓第一次跑，就逮到一个模板里把「英国」
写死成字段名的 bug——导致整份泰国报告在讨论英国市场份额，而这个 bug 在原案例下永远不会报错。
详见 [`docs/findings.md`](../docs/findings.md) 发现一。

```bash
PYTHONPATH=. python -m src.marketing_crew.main \
  --variant research_only \
  --brief-file briefs/herbeast_uk_v2.json
```

跑泛化性测试案例（花知晓 → 泰国）：

```bash
PYTHONPATH=. python -m src.marketing_crew.main \
  --variant research_only \
  --brief-file briefs/flowerknows_thailand.json
```

也可只跑可行性：`--variant feasibility_only`。

## 必填（最少）

| 字段 | 说明 |
|------|------|
| `product_name` | 产品/品牌名 |

## 建议填（越具体越好）

| 字段 | 说明 |
|------|------|
| `product_description` | 一句话 + 品类 |
| `market_scope` | 国家/地区 |
| `goals` | 希望报告回答什么（建议写成「进入条件/就绪度」） |
| `product_materials` | **最重要**：公开资料摘要、SKU、价格线索、链接 |
| `user_notes` | 侧重点、未知项、**期望报告效果案例**（见下） |
| `focus_areas` | 分析重点列表 |
| `constraints` | 硬约束（勿空引用、合规勿当否决等） |

## 可留空

| 字段 | 留空时 |
|------|--------|
| `known_competitors` | Agent 自行检索并说明理由 |
| `channel_priority` | V1 战略层即可 |
| `budget_range` | 写「未确定」，禁止编造 |

## 1. 可以在 Brief 里放「希望的报告效果案例」吗？

**可以，而且建议放在 `user_notes`（或 `constraints`）里。**

- **要写的**：好段落长什么样、坏段落禁止什么（结构/证据纪律/开场怎么写）。
- **不要写的**：把案例里的「假市场结论」当成事实；也不要整篇粘贴无关行业报告当「品牌资料」。
- Agent 会把 `user_notes` 整段喂进 prompt，所以案例要**短、可执行**（见 `herbeast_uk_v2.json` 里的「期望报告效果」一节）。

以后若要更强约束，可以再做成独立 `knowledge/` 评分样例；V1 用 brief 足够。

## 2. 没有品牌方一手资料时怎么找？

外部顾问常态。按这个顺序挖即可，挖到的链接写进 `product_materials`：

1. **官网 / 备案域名**（如 `herbeast.cn`）→ 品牌故事、产品线、成分叙事  
2. **中国区电商**（天猫旗舰店等）→ SKU 名、规格、标价截图级线索  
3. **主流媒体报道**（ELLE、新华网、行业媒体）→ 融资/入驻/奖项/实验室（当二手来源，数字要复核）  
4. **集合店新闻**（如 JOYCE Beauty 入驻稿）→ 渠道资产  
5. **百科 / 榜单** → 只作索引，重要数字必须另找原链  
6. **目标国公开页**（研究阶段再搜）→ gov.uk、英国零售商品页、竞品 £ 标价  

在 brief 里单独开一节 **「明确未知」**（RP 是否已定、UK 定价、是否已谈平台等），明确告诉 Agent：**不要编造**。

面试叙事可以说：模拟「只有公开信息的外部研究」，系统价值在结构化条件清单与可追溯来源，而不是假装有客户内部 BP。
